# 安装

## 方式一：脚本（推荐）

```powershell
git clone <本仓库地址> dsh-ai-gateway-console
cd dsh-ai-gateway-console
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Profile` | `desktop` | 目标 profile 名 |
| `-RepoPath` | 脚本的上级目录 | 插件仓库位置（一般不用给） |
| `-SkipProbe` | — | 跳过网关路径探测，稍后手动跑 `node scripts\probe.mjs --write` |
| `-SkipLink` | — | 只改 `package.json`，自己跑 `pnpm install` |

脚本会：

1. 备份 profile 的 `package.json`（`*.bak-before-aigw-<时间戳>`）
2. 写入 `dependencies.dsh-ai-gateway-console = link:<插件绝对路径>` 与 `dsh.profile.bundles` 条目
3. 建 `node_modules\dsh-ai-gateway-console` 的目录联接（junction）指向插件目录
4. 探测网关位置并写 `~/.dsh/ai-gateway-console.json`

**装完重启 DSH。**

## 方式二：手工（脚本被安全策略挡住时）

### 1. 改 profile 配置

编辑 `~/.dsh/profiles/<profile>/package.json`：

```json
{
  "name": "dsh-profile-desktop",
  "private": true,
  "dependencies": {
    "dsh-ai-gateway-console": "link:D:/somewhere/dsh-ai-gateway-console"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-ai-gateway-console"
      ]
    }
  }
}
```

要点：

- `link:` 后面用**正斜杠**，指向插件目录（含 `package.json` 的那层）
- 原有条目一律保留，只在 `bundles` 数组末尾追加
- 文件保存为 **UTF-8 无 BOM** —— 带 BOM 时 Node 的 `JSON.parse` 会直接抛错

### 2. 建目录链接

```powershell
$repo = 'D:\somewhere\dsh-ai-gateway-console'
$profile = "$env:USERPROFILE\.dsh\profiles\desktop"

New-Item -ItemType Junction -Path "$profile\node_modules\dsh-ai-gateway-console" -Target $repo
```

或者让包管理器来做：

```powershell
cd $profile
pnpm install
```

### 3. 生成配置

```powershell
node scripts\probe.mjs --write
```

## 方式三：只做状态页，不装控制台

插件本体（状态页、快照、日志、动作）**不需要 Python**。只要不点「启动控制台」，
就完全不碰 Python 那条线。想要完整控制台 UI 时再装 Python 3.10+ 即可。

## 多个 profile

插件目录只有一份，对每个 profile 各跑一次安装：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Profile desktop
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Profile default
```

配置是**全局共享**的（`~/.dsh/ai-gateway-console.json`），因为网关是机器级的，
不属于某个 profile。

## 验证安装

```powershell
# 1. 配置是否被正确读到
node scripts\probe.mjs

# 2. 全量自检
node scripts\doctor.mjs

# 3. profile 里是否登记成功
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json" | Select-String aigw
```

重启 DSH 后打开 `http://127.0.0.1:<dsh端口>/ai-gateway`，能看到服务卡就成功了。

## 排错

| 现象 | 原因与处理 |
|---|---|
| `/ai-gateway` 返回 404 | 插件没被加载。检查 `dsh.profile.bundles` 里有没有这个包名；确认**已重启** DSH |
| DSH 启动报 JSON 解析错 | `package.json` 被写成了带 BOM 的 UTF-8。用记事本「另存为 UTF-8」不带 BOM，或 `[System.IO.File]::WriteAllText($p, $json, (New-Object System.Text.UTF8Encoding($false)))` |
| 插件加载了但路径全是「未找到」 | `node scripts\probe.mjs` 看搜索根，把目录加进 `AIGW_SEARCH_ROOTS`，或直接在配置文件里写 `*.base` |
| 状态页能开但控制台起不来 | 没装 Python。`node scripts\doctor.mjs` 会列出候选路径；装了仍失败就在配置里写 `console.python` 绝对路径 |
| 控制器显示「未知」 | PowerShell 不可用或被执行策略挡住。只影响控制器那一格 |
| 端口 8330 被占 | 改 `cordis.patch.yml` 的 `consolePort`，或配置文件里的 `console.port` |

## 卸载

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1
```

默认保留 `~/.dsh/ai-gateway-console.json`（里面有路径与密钥，重装时还能用），
加 `-RemoveConfig` 一并删除。重启 DSH 生效。
