# 网关部署 —— 反代服务本身怎么装

本插件是**控制面**，它管的是下面这三个**数据面**服务。这份文档说明数据面怎么从零搭起来。

```
客户端（DSH / 任意 OpenAI 兼容客户端）
        │  OpenAI 协议
        ▼
┌───────────────────────────────────────────────┐
│  Trae 网关       127.0.0.1:8327   Trae CN     │
│  WorkBuddy 网关  127.0.0.1:8317   CodeBuddy   │
│  WorkBuddy Hub   127.0.0.1:8788   账号自动化   │
└───────────────────────────────────────────────┘
        │  各自的账号池（凭据文件 / 扫码登录）
        ▼
   上游服务商
```

三个服务的共同套路：**本地起一个 OpenAI 兼容端点，把上游的私有协议翻译成标准协议，
并在多个账号之间轮询分摊额度**。所以客户端只需要认一个 `baseURL` + 一个 key。

---

## 一、Trae 网关

### 是什么

把 Trae CN 的模型通道包装成 OpenAI 兼容 API 的 Python 项目（FastAPI）。
仓库名通常叫 `Trae2api-cn`，特征文件是 `web_login.py` 与 `src/main.py`。

### 部署

```powershell
git clone <Trae2api-cn 仓库> D:\tools\Trae2api-cn
cd D:\tools\Trae2api-cn

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 启动

项目自带两个 VBS 启动器（隐藏窗口后台跑）：

```powershell
wscript.exe launch-gateway.vbs   # 网关本体 → 8327
wscript.exe launch-auth.vbs      # 授权回调助手 → 8766
```

或直接：

```powershell
python -m src.main --port 8327
python web_login.py --port 8766
```

### 首次授权

1. 打开 `http://127.0.0.1:8327/web/login`
2. 点「使用 Trae 网页授权登录」——页面会检测本机 8766 的助手是否在线
3. 用 **Trae CN 账号**（手机号）登录并确认
4. 凭据自动写入网关，页面刷新显示「已登录」

验证：

```powershell
curl.exe -s http://127.0.0.1:8327/v1/status
# 关注 "has_token": true 与 "token_ok": true
```

### 添加第二个账号

**必须用隔离的浏览器会话** —— 授权页会用浏览器里已有的 trae.cn 登录态，
从普通窗口授权只会覆盖当前账号，而不是新增。项目自带的 `添加Trae账号.cmd` 就是干这个的：

```bat
start "" "C:\...\quark.exe" --incognito --user-data-dir="<项目>\.browser-profile-add" "http://127.0.0.1:8327/web/login"
```

关键在 `--user-data-dir` 指向一个独立目录，那个窗口里没有任何登录态。

### 模型命名

若客户端同时接了多个网关，同名模型会混淆，所以 Trae 侧给同名模型加后缀（默认 `（trae）`）：

```
glm-5.3  →  glm-5.3（trae）
```

入站方向会自动剥离后缀。开关在 `.env`：

| 变量 | 默认 | 说明 |
|---|---|---|
| `TRAE_MODEL_NAME_SUFFIX` | `（trae）` | 后缀文本，留空 = 关闭 |
| `TRAE_MODEL_SUFFIX_MODE` | `shared` | `shared` 只给同名模型加 / `all` 全加 / `off` 不加 |

## 二、WorkBuddy 网关

### 是什么

把腾讯 CodeBuddy / 混元反代成 OpenAI 协议的 **Go 单文件程序**（`workbuddy-gateway.exe`）。
特征是**多账号池**：轮询使用多个凭据均衡额度，账号触发 429 后自动冷却，由其余账号代偿。

### 部署

拿到 `workbuddy-gateway.exe` 放进一个目录，比如 `D:\tools\workbuddy-gateway\`。

### 登录账号

```powershell
# 国内站（微信扫码）
.\workbuddy-gateway.exe login

# 国际站（浏览器内完成）
.\workbuddy-gateway.exe login -intl

# 保存到指定文件（多账号）
.\workbuddy-gateway.exe login -auth workbuddy2.json
.\workbuddy-gateway.exe login -intl -auth workbuddy-intl.json
```

凭据文件命名必须是 `workbuddy*.json` —— 网关启动时按这个 glob 自动发现账号池。

### 启动

```powershell
.\workbuddy-gateway.exe serve -addr 0.0.0.0 -port 8317 -api-key <你的key>
```

`-api-key` 可选；设了之后客户端必须带 `Authorization: Bearer <key>`。

**隐藏窗口**：这是个控制台程序，直接启动会留一个黑框。用 VBS 包一层：

```vbs
' launch-gateway.vbs
Set sh = CreateObject("WScript.Shell")
sh.Run """D:\tools\workbuddy-gateway\workbuddy-gateway.exe"" serve -addr 0.0.0.0 -port 8317 -api-key <key>", 0, False
```

`Run(cmd, 0, False)` 的 `0` 就是隐藏窗口。

### 模型白名单

网关暴露的模型默认是上游的全量目录（几十个）。只想要一个：

```json
// config.json —— 必须 UTF-8 无 BOM
{
  "models": {
    "allowlist": ["deepseek-v4.1-flash"],
    "accounts": {
      "deepseek-v4.1-flash": { "allowlist": ["workbuddy-intl.json"] }
    }
  }
}
```

| 键 | 语义 |
|---|---|
| `allowlist` | **只暴露**列出的模型 |
| `blocklist` | 反向排除 |
| `accounts` | 把某个模型钉在指定凭据文件上（不写 = 按可用站点自动选） |

三个坑：

- 网关用 `DisallowUnknownFields` 解析 —— **多一个未知键整个文件就加载不了**
- 文件必须 **UTF-8 无 BOM** —— Go 的 `encoding/json` 见到 BOM 直接失败
- **不热加载**，改完必须重启网关

### 热加载的只有账号池

凭据文件的增删改是**每 5 秒扫描一次**的（`-reload-interval`，设 0 关闭），
所以加账号、换 token 都不用重启；只有 `config.json` 要重启。

## 三、WorkBuddy Hub（可选）

账号自动化 + 自带看板的 Python 服务（`wb-proxy`，端口 8788）。
提供扫码登录、签到、任务调度、用量分析等功能，界面比网关自带的多。

```powershell
cd <wb-proxy 目录>
.\start-hub.ps1
```

它不是必须的 —— 只想要模型通道的话，网关（8317）单独跑就够了。

## 四、后台控制器（可选）

网关自己不管「挂了怎么办」「免费额度优先用」这类策略，所以常见做法是几个常驻脚本：

| 控制器 | 干什么 | 存活判据 |
|---|---|---|
| 看门狗 | 轮询端口，服务掉线就拉起 | 互斥体 `Local\WorkBuddyServiceWatchdog` |
| 站点优先级 | 免费站点可用时把付费凭据移出池子 | 互斥体 `Local\WorkBuddyV41FlashPriority` |

它们**没有监听端口**，所以本插件靠**单实例互斥体**判断存活：控制器进程持有它直到退出，
内核在进程死亡的瞬间释放，因此「探测互斥体」等价于「探测存活」，且不受命令行嗅探那类误判影响。

写自己的控制器时保持这个约定即可：**用一个具名互斥体做单实例锁**，
既防重复启动，又让外部能零成本探测存活。

## 五、接入 DeepSeek Harness

网关起来后，在 DSH 的 profile 配置里加一个 provider。以 `cordis.patch.yml` 为例：

```yaml
- id: llm-pi-ai
  name: "@deepseek-ai/dsh-llm-pi-ai"
  config:
    providers:
      workbuddy-local:
        displayName: WorkBuddy 本地网关
        api: openai-completions
        baseURL: http://127.0.0.1:8317/v1
        headers:
          Authorization: Bearer <你的key>
        compat:
          thinkingFormat: deepseek      # 解析上游的 reasoning_content 思考字段
        defaultContextWindow: 262144
        defaultMaxTokens: 32768
        reasoning: max
        models:
          - id: deepseek-v4.1-flash
            name: DeepSeek V4.1 Flash
            contextWindow: 1000000
            maxTokens: 128000
            reasoningEfforts:
              off: none
              low: low
              medium: medium
              high: high
              max: max
```

几个容易踩的点：

- 字段名是 `baseURL`（大写 URL），不是 `baseUrl`
- 网关没启用 `-api-key` 时，`headers.Authorization` 用占位值也行，但不能省
- 每个模型的 `reasoningEfforts` 要按实测填 —— 缺这个字段时 DSH 会回退查内置 catalog，
  查不到就判定为 non-reasoning，带 `max` 的请求在发出前就报 `UNSUPPORTED_REASONING_EFFORT`

## 六、端口规划

一台机器上跑齐整套的话：

| 端口 | 服务 | 备注 |
|---|---|---|
| 8317 | WorkBuddy 网关 | |
| 8327 | Trae 网关 | |
| 8766 | Trae 授权助手 | 只在添加账号时需要 |
| 8788 | WorkBuddy Hub | 可选 |
| 8330 | 本插件的控制台 | 可选 |

挑端口前先 `netstat -ano | findstr :<port>` 看一眼，别撞上别的服务。

## 七、验收清单

搭完之后按这个顺序验：

```powershell
# 1. 三个服务的端口在听
foreach ($p in 8317,8327,8788) { Test-NetConnection 127.0.0.1 -Port $p -InformationLevel Quiet }

# 2. 网关能列模型
curl.exe -s -H "Authorization: Bearer <key>" http://127.0.0.1:8317/v1/models
curl.exe -s http://127.0.0.1:8327/v1/status

# 3. 真发一次请求（最有用的一步）
curl.exe -s -X POST http://127.0.0.1:8317/v1/chat/completions `
  -H "Authorization: Bearer <key>" -H "Content-Type: application/json" `
  -d '{\"model\":\"deepseek-v4.1-flash\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}],\"max_tokens\":8}'

# 4. 插件视角
node scripts\doctor.mjs
```

第 4 步全绿就说明控制面接上了。
